# Stage C evidence package — start here

**The question.** Can we improve COD accuracy by spending LAKE-RED's generation budget where the
model is weakest (allocating by teacher–student disagreement) instead of uniformly? That is the
E1/CSRDA-G "Stage C" extension.

**The answer.** No — and not for a fixable reason. The predicted gain is **0.031σ** against a **2σ**
detection bar, a shortfall of **~64×**, and no choice of budget, temperature, or seed count changes
that. Three independent measurements agree; one of them is a hard arithmetic identity.

**What this package is.** Every number behind that conclusion, regenerated by a committed script and
written to an append-only log with its timestamp, git commit, and command. No claim rests on prose.
**Nothing here trains a model** — the noise floor re-uses prediction files from six already-completed
runs.

## The bottom line, and which script proves each part

| # | conclusion | the number | script |
|---|---|---|---|
| i | The generator is near-unsteerable | its entire steerable channel is **48 scalars** (16 superpixels × 3 mean colours), while **~82%** of every output is invented background | `a1`, `a2` |
| ii | The training loop adds **zero** gradient steps for added data | `total_step` is pinned at 253 by the *target* loader, so every arm runs **9,867 identical steps** | `c2` |
| iii | The foreground pool is exhausted | **4447** foregrounds, **4447** generated outputs (4445 unique) — every addition is a *re-render*, not a new object | `d1` |
| iv | Targeted and random data are nearly identical | **Cohen's d ≈ 0.10**, invariant across a 10× temperature sweep; the pool shift peaks at B=2000 for **1.26×** and hits **0** at B=4447 | `c1`, `c2` |
| — | so the effect cannot be detected | predicted **ΔSα = 0.000111 = 0.031σ** vs **2σ = 0.00712**; clearing the bar would need **d = 7.09**, while the entire real-vs-synthetic gap is d = 4.70 | `c3` |

**What survived as valid** — this is not only a takedown:

- **Uncertainty is a real weakness signal.** ES-disagreement predicts per-cluster true error at
  **ρ ≈ +0.82** (MAE), replicating at **+0.903 ± 0.041** across four independent runs. (`b1`)
- **Targeting genuinely works.** ~**20%** held-out acceptance, **12–16×** above chance,
  p ≈ 1e-112 — an earlier "0%, this is dead" verdict was an artifact of a weak embedder. (`b3`)
- **Dropping the coverage term was correct.** λ_cov = 0 is measured, not assumed, and is defensible
  **without labels**. (`b2`)

## Where we are, and how we finish

**Done.** E0, the gate. Every irreplaceable input — 6 noise-floor prediction directories (12,156
files), 12 checkpoints, 39 feature caches — was sitting in a volatile `/tmp` scratchpad and is now on
durable disk with committed hashes. Losing it would have made the noise floor recoverable only by
6 × 1.8 h of retraining.

**Important caveat while reading.** The numbers in `EVIDENCE_APPROACH.md` and `EVIDENCE_SCRIPTS.md`
are currently the **expected** values, carried over from the two prior audits. They are *not yet*
re-measured by the committed scripts. Only the log tells you what has actually been verified — right
now that is E0 alone. Treat any number without a log block as a claim awaiting reproduction.

**The loop for each remaining experiment.** One experiment, one commit, no batching:

1. Write the script; its header states the objective, the source it reproduces, and any revision it
   surfaces.
2. Run it. It appends **one block** to the log: measured value beside the expected one.
3. If they disagree, correct the markdown **in that same commit**, so the history shows the
   disagreement instead of hiding it.
4. Commit as `evidence(A1): ...` — script, log block, CSVs, nothing else.
5. Stop, report the block, then start the next.

**What "finished" looks like.** Twelve log blocks, twelve commits, and every number in
`EVIDENCE_APPROACH.md` traceable to one. At that point the package supports one decision: **do not
run the 84-run A/B/C ablation as a positive allocation claim.** The measured prior is 0.031σ against
a 2σ bar; a null there would cost days of compute to confirm what the arithmetic already gives.

**Verify it yourself** — from the repo root:

```bash
sha256sum -c evidence/manifests/MANIFEST.sha256      # 81 rescued inputs
sha256sum -c evidence/manifests/SOURCES.sha256       # the 3 immutable source documents
LAKE-RED/.venv/bin/python evidence/e0_rescue.py --dry-run
```

## Honest limits

- **This does not show generation-in-the-loop cannot work.** It shows *this* generator, at *this*
  conditioning width, with *this* exhausted foreground pool, inside *this* fixed-step loop, cannot
  deliver a detectable Sα gain. A new foreground source would change the scope.
- **The effect translation assumes linearity from a single anchor point.** Stated as an assumption,
  not a measurement — it is the one genuine escape hatch, and it leans *generous* to the proposal.
- **Some claims are permanently unverifiable.** The iteration-2 pool directories were deleted, so
  `|Ds|` = 6824/7824 and "the pool is 30–35% real" are carried as audit citations marked
  NOT-REPRODUCIBLE. `D1` re-scopes to what survives, which is the load-bearing part.
- **`Dataset/Val/CAMO` is 250/250 byte-identical to `Dataset/Test/CAMO`**, so every checkpoint in
  every arm is selected on a test set. It cannot bias the B-vs-C contrast, but CAMO can never be
  reported as an endpoint. (`d2`)

**The forward path, if the direction is worth rescuing.** One experiment has never been run and is
the difference between a paper that describes a failure and one that prescribes a fix: **widen the
conditioning channel** — concatenate a target-cluster embedding into the cross-attention at
`ddpm.py:1579` — and show that acceptance *and* generative recall both rise. That attacks the actual
bottleneck (48 numbers; recall 0.466 against a 0.939 ceiling) instead of measuring a lever we have
now shown to be weak.
