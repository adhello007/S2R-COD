all of `rebuild/`.

## 2. What D1 must respect, from D2

Two D2 findings would make a naive D1 assert something false:

1. **Distinctness is pool-dependent** (D2 s3). The three HKU-IS pools do not have the same number of
   unique files. "4447 distinct foregrounds" is a *file count*, not a distinctness claim. D1 reports
   per-pool unique counts and reconciles them against D2's, treating any disagreement as a defect.
2. **A render is keyed by (foreground, mask, position-in-shard)** (D2 s7/s8), not by the foreground
   alone. So "the render pool is determined by the foreground pool" holds only at a **fixed shard
   count over a fixed input listing**. D1 carries that qualifier rather than dropping it.

## 3. Steps

| Step | What it does |
|---|---|
| **s1 verify** | Re-hash a random sample and check against E0's manifest — the rest is consumed, not recomputed |
| **s2 pools** | Per-pool unique counts for raw / authors' / local, reconciled against D2's measured values |
| **s3 polarity** | Measure the white-pixel fraction of **every file of every mask set** and assert each one's polarity at run time (trap T2) |
| **s4 bijection** | Stem-level mapping: does the render set map onto the raw foreground set? Injective and surjective? Same for the authors' pool |
| **s5 literal** | Pixel-level: does each render actually carry its source object pixels? Run over all 4447 for **both** pools |
| **s6 scope** | The position qualifier, read from D2's output rather than re-measured |

### Why s3 measures rather than assumes

A silent polarity flip would invert the object region and corrupt the foreground↔render mapping in
s4/s5 **while leaving every count intact**. That is a defect no count would catch, so polarity is
measured over all 4447 of each of the four mask sets, never taken from documentation.

### Why s5 scores each pool against its own mask

The local renders were staged from `raw_gt` (`prepare_lakered_inputs --src_masks HKU-IS_raw/gt`); the
authors' pool ships its own GT, which s3 measures as *different* (trap T3). Scoring the authors' pool
against `raw_gt` counts pixels its own mask called background — which were genuinely regenerated —
and inflates the object error. s5 therefore pairs each pool with the mask it was rendered with, and
additionally scores an **eroded interior**, because for a small object the mask boundary is a large
fraction of the region and the boundary is exactly where the two mask sets disagree.

This was found by auditing D1's own first run — see `D1_RESULTS.md` §3.4.

## 6. Known limits, declared

- **D1 does not establish that new foregrounds could not help.** It bounds only what *this* pipeline
  can add from its *fixed* pool. It is silent on whether a larger or different foreground set would
  change any outcome.
- **Pixel-level and pool-internal.** Near-duplicate foregrounds *within* the pool are D2's scope and
  pixel-level only. Two visually similar but non-identical foregrounds count as two.
- **The position qualifier.** One foreground can yield many different renders (D2 s8). That is a
  **background** degree of freedom; the object pixels come from the pool either way.
- **`obj_interior_mean > 40` is a chosen cutoff** for "plausibly regenerated". It is reported as a
  count at a stated cutoff, not as proof of a mechanism.
- **s1 verifies a sample**, not all 31129 hashed files in the seven sets D1 touches. It detects
  wholesale drift, not a single altered file.
