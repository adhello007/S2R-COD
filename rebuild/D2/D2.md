## 2. Method

**Detection is by hash, never by name.** Phase 0 established that only 2 of the 7 previously claimed
Target/COD10K duplicates share a filename; the other 5 are cross-named and invisible to any name
check. One was additionally mis-transcribed in the old documents — `COD10K-CAM-3-Flying-53-Owl-4633`
does not exist; the file on disk is `Flying-65`.

Two hash levels per image:

| Level | Definition | Catches |
|---|---|---|
| `fhash` | SHA256 of the file bytes | identical files under any name |
| `phash` | SHA256 of `(shape, decoded RGB bytes)` | additionally, re-encodes that decode to the same pixels |

### Steps

| Step | What it does |
|---|---|
| **s1 hash** | Hash every image in all 8 splits, in parallel |
| **s2 cross** | Every unordered split pair, at both hash levels; emits the full pair matrix and every collision |
| **s3 internal** | Duplicates *within* each split, at both levels |
| **s4b endpointNN** | Nearest same-dimension *training* image for every endpoint image, with gap detection — shows whether s4's count is a data boundary or a cutoff artifact |
| **s4 near** | Re-encoded near-duplicates, **exhaustive within every exact-dimension group**: a 32×32 descriptor shortlists via Gram matrix, then every survivor is verified at full resolution. Then per-endpoint contamination and a **tolerance sweep** |
| **s5 mae** | What the contaminated test images do to the reported endpoint, using `Eval/metrics.py` |
| **s6 scope** | Read `--val_root` out of `MyTrain.py` and assert the checkpoint-selection set is a published test split |
| **s7 determin** | Is a render a function of its input? Found via s3 — see below |
| **s8 seedtest** | **Controlled** test of s7's mechanism: three byte-identical inputs generated at different and at equal shard positions. Needs a GPU (~6 min) |

### s4's status, and its rewrite

s4 began **exploratory and unthresholded**, because D2's declared scope in `REBUILD_PLAN.md` is pixel
identity. It earned a threshold during execution once it showed that pixel identity under-bounds the
claim by an order of magnitude on one endpoint. That threshold was added **after** the pair count was
known but **before** the per-endpoint breakdown was computed; the disclosure is in the log block, and
the resulting FAIL is recorded as a FAIL rather than relaxed.

**s4 was then rewritten.** Its first implementation bucketed images by a contrast-normalised 16×16
thumbnail hash and compared only within a bucket — roughly **27 % recall**, established by auditing it
against an exhaustive search. Contrast normalisation destroyed the discriminative scale and hard
bucket edges split true pairs. The current version is exhaustive over the only pairs that can be
pixel-comparable (equal dimensions), so nothing in scope is missed for want of a bucket. See
`D2_RESULTS.md` §3.2.

### s8's status

s8 was not planned either. s7 *inferred* a mechanism from 4 observational pairs; s8 **tests** it by
construction, including a positive prediction (force equal shard positions → divergence must vanish).
It runs the generator but trains nothing.

### s7's origin

s7 was not planned. s3 found that the raw HKU-IS pool contains byte-identical image pairs, and that
the render pool contains fewer identical pairs than the input pool does — which should be impossible
if a render is a function of its input. s7 tests the mechanism against every duplicate pair.

## 4. Declared thresholds

| Step | Condition |
|---|---|
| s1 | Every split count matches the E0 manifest |
| s2 | Byte- and pixel-level agree on \|COD10K-test ∩ Target\| — a method-consistency check |
| s2 | No endpoint image appears in any HKU-IS pool |
| s2 | Leaked-name contract emitted and non-empty |
| s4 | No endpoint has > 5 % of its images as re-encodes of training data *(added mid-run; see §2)* |
| s4b | CHAMELEON's nearest-neighbour distances show a clean separation, so the matched count is a property of the data, not the tolerance |
| s8 | T1 identical inputs at different positions differ; T2 an identical invocation reproduces bit-exactly; T3 forcing equal shard positions makes renders identical |
| s5 | Removing contaminated test images moves MAE by < 0.001 |
| s5 | Contaminated images show no memorisation signature — mean percentile in 0.25–0.75 |
| s6 | Checkpoint selection runs on the CAMO split, so CAMO is excluded as an endpoint |
| s7 | Render identity across duplicate inputs is fully explained by (mask identity **and** shard-local position) |

---

## 5. Declared limitation

**Pixel identity bounds the primary sweep.** s4 extends coverage to rescaled and re-encoded
duplicates. Crops, flips, colour-shifted copies, and different photographs of the same specimen are
**not** detected and are not claimed. This is a lower bound on contamination, never an upper one.
