## 1. Scripts

| Script | Role | Author |
|---|---|---|
| [`rebuild/common.py`](../common.py) | Shared: input registry, image loaders, embedder, hashing, log format | this rebuild |
| [`rebuild/E0/e0_regenerate.py`](e0_regenerate.py) | The experiment; all five steps | this rebuild |
| `LAKE-RED/src/lake_red/prepare_lakered_inputs.py` | Invoked by step s4 to stage inverted masks | pre-existing, unmodified |
| `LAKE-RED/test.py` | Invoked by step s4 to generate renders | pre-existing, unmodified |

`common.py` is shared rather than copied into each experiment folder on purpose: it is the single
definition of the embedder and of the image loaders. The previous package had two different
embedder definitions live at once (fp16 in the cache builder, fp32 in the reusable helper) — trap
**T4** in `REBUILD_PLAN.md` §2. One definition makes that class of drift impossible.

Nothing in `rebuild/` reads the archived old artifacts or any `/tmp` scratchpad. Step **s5** asserts
this mechanically rather than trusting it.

### Commands run

```bash
# steps s1, s2, s3, s3b, s5  (CPU + 1 GPU, ~25 min)
LAKE-RED/.venv/bin/python rebuild/E0/e0_regenerate.py \
    --steps s1,s2,s3,s3b --batch 48

# step s4 -- render regeneration (2 GPUs, ~70 min)
LAKE-RED/.venv/bin/python rebuild/E0/e0_regenerate.py \
    --steps s4 --ngpu 2 --batch 48

# provenance gate, run last
LAKE-RED/.venv/bin/python rebuild/E0/e0_regenerate.py --steps s5
```

`--no-log` formats a block without appending to the log; used while iterating so that fixing a
defect in measurement code does not leave a trail of near-identical blocks. Only accepted runs are
logged.

## 2. Steps

| Step | What it does | Why it is here |
|---|---|---|
| **s1 manifest** | SHA256 every file in all 15 declared input directories | The anchor every later block cites, and a tripwire. `Dataset/Test/CAMO` was removed mid-audit on 2026-08-30 and was only noticed by accident; with a manifest that is detected, not noticed |
| **s2 represent** | Pixel-level verification of every representation claim in `REBUILD_PLAN.md` §2 and traps T1–T3 | Where the previous package's grey-128 slip lived. Every check opens the actual files; no variable name or docstring is taken as evidence |
| **s3 embed** | Feature caches: 2 embedder families × resolution sweep × 7 sets | The shared substrate for B1, B2, B3, C1 |
| **s3b resize** | Squash-resize vs aspect-preserve + centre-crop: does the choice move cluster membership? | An unjustified constant inherited from the old package. `REBUILD_PLAN.md` §0.2 says measure such choices rather than adopt them |
| **s4 renders** | Re-stage and re-generate the 4447 LAKE-RED renders at `--seed 0` into a **new** directory, then compare to the pool on disk | "Regenerate, don't rescue" applied to the largest artifact |
| **s5 independent** | Grep every `rebuild/*.py` for archive / scratchpad / rescued-cache references, and resolve every declared input | The provenance gate. A passing grep is the proof that no rescued dependency survives |

### What s2 verifies, and against what

| Check | Claim under test | Method |
|---|---|---|
| polarity | HKU-IS GT stores the object as **white** | Compare mean foreground fraction against mean *border* whiteness. Salient objects rarely tile the frame edge, so an object-white mask has a near-black border |
| cutout (**R2**) | The "foreground cutout" is object-on-flat-grey-128 | Open a cutout, take the pixels where mask `< 127`, assert `np.unique` is exactly `{128}`; separately assert the object pixels equal the source |
| **T1** | The three 4447-image HKU-IS pools are mutually non-identical | Pairwise `maxdiff` over 200 stems: raw photographs vs authors' pool vs local renders |
| **T2** | LAKE-RED input masks are inverted, output masks flip back to SOD polarity | Compare white-pixel fraction across GT → staged input → saved output |
| **T3** | `Source/HKU-IS/GT` differs from `HKU-IS_raw/gt` | Byte comparison over 200 stems plus the foreground-fraction delta |
| **isReplace** | `test.py:165` composites the source foreground back into the render | Split the per-pixel absolute difference between render and source into object and background regions and compare. A lossy JPEG re-encode cannot give bit-identity, so the honest test is the **ratio**, not equality |

## 4. The embedder, as declared

Declared in [`rebuild/common.py`](../common.py) `EMBEDDERS`. **Not reverse-engineered.** The previous
package had to reconstruct its preprocessing by testing eight candidate pipelines against saved
vectors, because the producing script was gitignored; two near-misses (centre-crop, `INTER_AREA`)
would have silently produced slightly wrong features.

| Tag | Model | Size | Family |
|---|---|---|---|
| `dinoL224` | `vit_large_patch14_dinov2.lvd142m` | 224 | self-supervised |
| `dinoL518` | `vit_large_patch14_dinov2.lvd142m` | 518 | self-supervised |
| `clipL224` | `vit_large_patch14_clip_224.openai` | 224 | language-supervised |

- **Two families** so no conclusion is embedder-specific (`REBUILD_PLAN.md` §0.2).
- **Resolution sweep** because the old package's acceptance headline moved 4.1× between 224 and 518.
- **Precision fp32.** The old caches were fp16 (`embed_dino.py:6` `.half()`). A deliberate difference,
  recorded rather than matched.
- **Normalisation from each model's own `pretrained_cfg`.** CLIP's mean/std is not ImageNet's; using
  one for both would quietly corrupt the second family.
- **Resize:** squash to `(S, S)` BICUBIC — the whole frame is kept, nothing cropped, aspect distorted.
  A choice, so s3b measures what it costs.
- **Pooling:** CLS token *and* patch-mean, both stored, so no experiment re-embeds to change pooling.
- **Storage:** unnormalised; L2 at use time via `common.l2`.

## 5. Thresholds

Declared before the run, in `e0_regenerate.py`.

| Step | Condition |
|---|---|
| s1 | Every declared input present and count matches |
| s2 | HKU-IS GT stores the object as white |
| s2 | Cutout background is exactly the flat value 128 |
| s2 | Cutout leaves object pixels untouched |
| s2 | The three HKU-IS pools are mutually non-identical |
| s2 | LAKE-RED input masks are inverted (object = 0) |
| s2 | LAKE-RED output masks return to SOD polarity |
| s2 | Authors' GT differs from raw GT |
| s2 | `isReplace`: background error exceeds foreground error by ≥ 5× |
| s3 | Every cache row count equals its declared input count |
| s3b | Resize policy moves < 10 % of images between clusters |
| s4 | Regenerated renders keep ≥ 95 % of cluster assignments |
| s5 | No rebuild script references the archive or a `/tmp` scratchpad |
| s5 | Every declared input resolves from primary data |

**s4's threshold was written as cluster agreement, not byte-identity**, on the expectation that
cuDNN nondeterminism would prevent bit-exact reproduction. **That expectation was wrong.** All 4447
regenerated images *and* all 4447 masks are byte-identical to the pool on disk (verified three ways:
per-file SHA256, whole-directory aggregate hash, and decoded-pixel diff — see the log block). The
cluster-agreement threshold therefore passes at 1.0 trivially, because identical bytes give identical
embeddings; byte-identity is the stronger result and subsumes it. Both are recorded.

Scope of that claim: LAKE-RED at `--seed 0` is bit-exactly reproducible **on this machine with this
software stack** (torch 2.11.0+cu128, CUDA 12.8, RTX PRO 6000 Blackwell). It is not a claim that the
pipeline is deterministic in general, across hardware, or across driver versions.

## 7. Known limits of E0

- **s2 samples.** Polarity is checked on 400 stems, the remaining checks on 50–200. These are
  existence/consistency proofs, not distributions — A2 measures the foreground fraction over all
  4447, and D1 hashes every file.
- **`cut` is never written to disk.** Only its embeddings are cached, so verifying the cutout
  representation means re-running s2, not inspecting an image directory. Deliberate: a materialised
  cutout pool is a fourth thing that can drift out of sync with the mask set that defines it.
- **s4 regenerates at `--seed 0` only.** Generator variance across seeds is not measured here and is
  not claimed. Bit-exact reproduction at a fixed seed says nothing about how much the render pool
  would move at a different seed — which is the quantity a best-of-K selection scheme would depend on.
- **The archive is not consulted for cross-checks in E0.** Comparisons against the old package's
  values happen per-experiment in each `OLD CLAIM` line and in `REVISION_TABLE.md`, from the frozen
  record in `REBUILD_PLAN.md` §4 — not by reading archived arrays.
